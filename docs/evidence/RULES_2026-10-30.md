# Configurable X01 and sets — 30 October 2026

v0.9 extends SC-01 and the shared input/data contracts. This does not complete the full game catalogue, participant or match-lifecycle workstreams.

## Supported configuration

- Whole-number starts from 101 through 1001, with 301/501/701/1001 presets.
- Straight or double in, independently combined with straight or double out.
- First-to 1–11 legs, or first-to 1–11 sets with a separate first-to leg target per set. No win-by-two or deciding-set tie-break policy is implied.
- Selected first thrower. Alternate every leg across the match, or alternate set starters and then alternate legs within each set. The latter is available only for sets.

The UI shows these choices before play and identifies them on the playing screen and in history. Per-set legs, total legs and sets won are distinct values. A set winner can legitimately have fewer total legs than the opponent; result ownership and archive/profile records use the match winner, not the larger total-leg count.

## Opening, finish and input policy

Darts before an opening double do not score. The double itself and subsequent darts do. Inner bull can open or finish as a double. A bust cancels the entire visit, including an opening double; the next visit still needs to open. This is an explicit local format policy, not a claim of compatibility with every organiser’s rules. The opening/bust definitions were checked against the [GVDA league rules](https://www.thegvda.org/paperwork/rulesw2022.pdf), including its explicit double-in bust policy in section 2.4 D.4. Other league-specific rules in that document are not implemented or advertised.

Double-out retains leaving-one and non-double-zero busts. Straight-out permits one remaining and reaches zero on any scoring segment. Both modes reject an overshoot; detailed visits stop immediately on bust or checkout.

Board entry stores the actual hits and computes the credited score. Aggregate input requires an explicit opening declaration while closed and records only the declared credited total, dart count and finish confirmation. It does not invent individual hits. A precomputed legality table checks opening and finishing together: e.g. 101 cannot both double in and double out in two darts, even though the same total is possible under other formats. Checkout suggestions and practice opponents follow the selected rules.

All declared/recorded darts, including attempts before opening, count in the current weighted average. Profile records are labelled as combining retained local X01 formats; no verified ranking or cross-format skill equivalence is claimed.

## Saved-data compatibility

Old v1 sessions keep straight-in/double-out legs rules and their original commands. New games use session v2. Import/migration preserves the version and recognised rule fields; v1 records cannot silently adopt v2 rules. Older releases that only understand session v1 reject the new session version instead of replaying it with their defaults. Unknown future versions remain rejected. The surrounding workspace/backup envelope versions are unchanged because their data boundaries are unchanged; session versions identify scoring semantics.

Draft identity includes the full versioned session. Draft validation uses the current opening/finish state and retains an aggregate opening declaration. Export, import-worker review, archive reconciliation, undo/redo, set transitions and linked-profile totals replay the selected rules.

## Verification

- Domain fixtures cover legacy results, start/settings bounds, all four opening/finish combinations, opening misses/bull/bust, combined opening/checkout feasibility, leaving one and a single finish.
- Detailed/aggregate equivalence is checked across 1,372 representative three-dart sequences. Every returned checkout route from 1–180 is evaluated under its declared rule combination.
- Set fixtures distinguish starter policies, reset within-set legs, preserve immutable previous state and replay correction. A 2–1 set win with a 6–7 total-leg loss survives backup/import and profile aggregation.
- Simulated darts are validated across all rule modes, opening states and deterministic seeds.
- Four browser journeys cover double-in board draft recovery, aggregate declaration/invalid finish, straight-out single-point finish and set advancement/refresh/correction/export/import review.
- Fresh Chromium rendering at 1366 and 390 CSS pixels handles four-digit scores and set progress without horizontal overflow.

Local verification: TypeScript and production build pass; 114 unit tests, 41 development-browser tests and five production offline/update tests pass.

## Remaining gates

Bull-off, richer match-policy configuration, concessions/pause/abandon/rematch, participant/side rotation, other games, statistics filtering, physical-device usability and server parity remain outstanding. Storage/action/import limits and browser persistence limitations still apply. Passing these fixtures does not establish official event certification or production readiness.
