# Local data reliability — 30 October 2026

Implemented in v0.7 on the existing foundation branch. This is a local-data increment, not acceptance of the complete sync/offline workstreams.

## Behaviour

- One versioned IndexedDB document holds the match, archive and player profiles. Read/write transactions compare revisions and prevent a stale tab replacing newer changes.
- Readable legacy local-storage data migrates once; original strings remain intact. Malformed legacy or newer unreadable documents are preserved with explicit recovery actions. Storage failures remain visible; a successful profile save cannot hide a failed match save.
- Full JSON backup includes readable current data. Import review runs in a worker, checks rules/schema/version and the 20 MB limit, and recomputes results. Names alone never merge player identities.
- Duplicate results skip; conflicting IDs require an explicit separate copy. Restoring an open match requires a separate choice and acknowledgement before replacing an existing game. Imports cannot silently prune the 100-player/result limits.
- Import and pre-import recovery snapshot commit atomically. A failed transaction changes neither. Undo requires the imported revision still be current; the preceding snapshot remains downloadable after later changes.
- Standalone imported matches keep guest identity. Imported results are labelled and do not constitute verified online/tournament records.

## Verification

Repository tests use fake-indexeddb for migration, transactional rollback, stale revisions, queued writes, recovery and save-state failures. Backup tests cover identity linking, duplicate/conflict handling, malformed/newer files and limits. Six browser workflows exercise actual file upload/download, restore/reload, replacement confirmation, failed transactions, multiple tabs and unavailable storage, alongside existing scoring/profile/practice regression tests.

## Remaining acceptance work

Turn drafts, installable/offline/update behaviour, configurable retention, cross-device sync, broad real-device and performance validation remain outstanding. Browser data clearing still removes this device’s database; downloaded backups must be kept separately. No account/cloud recovery is claimed.
