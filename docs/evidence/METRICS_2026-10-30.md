# Recorded score evidence — 30 October 2026

Scope: local IN-03 capability/source flags and PL-02 metric definitions, application v0.13. This is not acceptance of online provenance, rankings, adapters or a complete profile analytics product.

## Authoritative implementation

- `src/domain/metrics.ts` defines `x01-recorded-v1`, one weighted calculation for side, participant and profile score metrics, plus explicit sample coverage and unsupported-capability flags.
- `src/domain/match.ts` validates source labels and derives origins from the actual thrower/practice role during replay. `src/App.tsx` labels new v5 visits at the input boundary. Total-only input never receives generated segments; segment input never receives generated coordinates or targets.
- `src/data/workspace.ts` preserves supported source labels through canonicalisation. Existing schema-v5 events may omit the additive label; versions 1–4 retain their stored shape and unknown human origin. Replay, not an input file’s derived result/verification fields, determines evidence.
- Profile statistics use only each linked participant’s visits, filter practice/format as before, count imported/combined-rule samples, and share the match statistics implementation. No data migration or retained record rewrite is needed.
- `ScoreEvidence` exposes sample sizes, entry origins, weighted formula, bust/double-in treatment, side/member outcome distinctions, unavailable metrics and the definition version in history/profile screens. History labels each visit’s input. The detailed disclosure stays collapsed until opened.
- [Metric contract](../METRICS.md) specifies denominator, retained-history limits, sample scope, definitions, label trust and future source/authority gates. Match exports identify the derived metric definition; imports replay commands and ignore derived aggregates.

## Verification

`src/domain/metrics.test.ts` adds 20 cases, including expanded fixtures:

- Empty sample is unavailable/incomplete, never vacuously complete or verified.
- Mixed segment/total evidence reconciles visits/darts without inventing detail; complete segments still do not imply targets, coordinates, checkout attempts or competitive verification.
- Versions 1–4 project unknown human origin without mutation; early v5 omission remains unknown. Supported v5 source labels survive canonicalisation, invalid labels/roles/detail combinations fail replay, normalisation and import review.
- Legacy bot origin derives from the bot side rather than name or source claim. Human-labelled bot scores and simulated human scores are rejected.
- Misses, unopened visits, busts, double-in checkout and actual recorded dart counts use one definition. Profile averages weight total points/darts across matches with different recorded dart counts, rather than averaging their averages.
- Import/rule configuration counts and duplicate filtering reconcile with the accepted profile sample. Backup review/import/export preserves coverage without upgrading verification. Forged derived origins, coordinates and verification fields are ignored.
